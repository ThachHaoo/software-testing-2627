### 3.3 Assertion

<!-- REPORT:A_FR01:assertions:BEGIN -->
_Chép nguyên văn từ `A_FR01/assertions.md`._

#### 4 kiểu assertion

| Kiểu | Matcher | Kiểm gì |
|---|---|---|
| UI – trạng thái | `toHaveURL`, `toBeVisible` | URL sau khi bấm "Đăng Ký" (`/login` hoặc vẫn `/register`); hộp lỗi đỏ hiện |
| UI – nội dung thông báo | `toHaveText`, `toContainText` | hộp lỗi có chữ; thông báo nhắc đúng trường/điều kiện mà expected nêu |
| Oracle dữ liệu qua API | `toEqual` | `GET /api/admin/users` trước/sau: danh sách user mới (name, email), user seed không bị sửa/xoá; không gửi `POST /api/register` (A16) |
| Đếm / giá trị | `toHaveValue`, `toHaveCount` | ô trống khi mở form và hiện đúng chuỗi đã gõ; số hộp lỗi = 0 khi expected "Không có thông báo lỗi" |

> - Selector phụ thuộc cấu trúc DOM và thẻ HTML chung chung: cảm giác script kiểm tra hình minh hoạ giỏ giống bằng selector main img, main svg không đủ tốt lắm.Vậy nên dễ nhầm nếu trong \<main\> có icon khác hoặc fail nếu UI dùng \<canvas\>
> - Assertion phụ thuộc chặt vào câu chữ tiếng Việt cụ thể: Các assertion đang khớp hardcode text. Nên nếu đổi thông báo thì lại fail.
> - Cách bắt sự kiện dialog: script gắn listener page.on('dialog', ...) và tự động accept() ngay lập tức. Nên cái này chỉ check có bật dialog hay không chứ không kiểm tra được trạng thái UI tạm dừng.
